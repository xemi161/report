# UI 피드백 백로그 (구현 전 메모)

실제 앱을 띄워 확인하면서 나온 자잘한 개선 아이디어를 모아두는 문서. 각 항목은 **아직 구현하지 않았고**,
착수 시점에 별도로 스코프를 정한다(설계가 필요하면 design 에이전트부터).

## 1. 작성 화면 — 세부 항목의 시간/일 입력란이 불명확 (2026-08-15)

**증상**: 주간보고 작성 화면에서 세부 항목 행의 "투입시간"/"일수" 입력란이 뭘 입력해야 하는지 명확하지 않음
(사용자 직접 관찰, 구체적으로 어떤 부분이 헷갈리는지는 아직 추가 확인 필요 — 라벨 위치, 단위 표기, 두 칸의
시각적 구분, placeholder 부재 등 후보만 있고 원인은 미확정).

**현재 구조** (`src/main/resources/templates/fragments-entry.html`):
- 컬럼 헤더 `투입시간`/`일수`는 항목이 있을 때만 표시(`hours-input`/`days-input` span).
- 각 행은 `시간 [투입시간 입력] · 일 [일수 입력] 일` 형태 — `effortFields` 프래그먼트(라인 65~71 부근),
  `hours`는 `step="0.5"`, `days`는 `step="1" min="1" placeholder="1"`(비우면 1일로 저장, `daysOrDefault()`).
- 개발/기타 항목 등 일부 변형 행(라인 121~146 부근)은 **`hours`만 있고 `days` 칸이 아예 없는 경우도 있음** —
  화면마다 입력란 구성이 달라 "명확하지 않다"는 인상에 한몫할 가능성.

**다음에 할 일**: 실제로 어떤 지점이 헷갈리는지(라벨/배치/단위/일관성 중 무엇) 사용자와 한 번 더 확인한 뒤,
필요하면 design 에이전트로 목업부터 다시 짤 것. 구현 착수 전.

## 2. "이번 주에 한 일" 날짜 선택에서 토요일/일요일 제거 (2026-08-15)

**요청**: 작성 화면 좌측 "이번 주에 한 일" 패널에서 새 기록을 추가할 때 뜨는 날짜 선택(요일 드롭다운)에
토요일/일요일이 안 나왔으면 좋겠음.

**현재 구조**: `DailyNoteController.populateWeekPanel()`가 `panelDates` 모델 속성을 그 주 7일(금~목) 전부로
채워서 `fragments-daily.html`의 `weekPanel` 프래그먼트 `<select class="date-sel" name="workDate">`가 7개
옵션을 전부 그린다.

**적용 방향(초안, 구현 전)**: `panelDates`를 만들 때 `DayOfWeek.SATURDAY`/`SUNDAY`를 건너뛰면 됨(5일만 옵션에 남음).
기존에 주말에 적어둔 기록(`panelDayGroups`)은 이 필터와 무관하게 그대로 보여야 함 — 건드리는 건 "새로
추가할 날짜" 선택지뿐, 이미 있는 기록을 숨기는 게 아님. `panelDefaultDate`가 오늘(토/일)을 가리키던 경우의
대체값도 같이 정해야 함(예: 그 주 마지막 평일로).

**다음에 할 일**: 구현 착수 전 — 별도 요청 시 처리.

## 3. "이번 주에 한 일" 목록에 기록 복사 버튼 (2026-08-15)

**요청**: 작성 화면 좌측 패널의 기록 각 줄에 텍스트를 복사할 수 있는 버튼이 있었으면 좋겠음 — 오른쪽
주간보고 폼에 그대로 붙여넣기 위한 용도로 추정.

**현재 구조**: 기록 한 줄은 `fragments-daily.html`의 `dailyRow` 프래그먼트 하나를 대시보드/작성패널/
히스토리 세 화면이 전부 공유한다(텍스트 textarea + 시간 입력 + 삭제 버튼). 클립보드 복사는 서버 왕복이
필요 없는 순수 클라이언트 동작이라 `app.js`(htmx 이벤트 델리게이션과 같은 자리)에 추가하면 됨 — 백엔드
변경은 필요 없음.

**적용 방향(초안, 구현 전)**: `dailyRow`에 아이콘 버튼 하나 추가(`data-copy-text` 속성에 텍스트 담기),
`app.js`의 클릭 델리게이션에 `navigator.clipboard.writeText` 핸들러 추가하고 기존 `showToast`로 피드백.
셋 중 어느 화면에만 넣을지(질문상 "이번 주에 한 일"만 언급 — 대시보드/히스토리 기록도 같은 컴포넌트라
넣으면 셋 다 적용됨, 그게 맞는지 확인 필요) 결정 필요.

**다음에 할 일**: 구현 착수 전 — 별도 요청 시 처리.
