# 주간 업무보고 프로그램 — 설계 요약 (Claude Code 전달용)

이 문서는 아이디어 정리 단계에서 확정된 설계 내용을 정리한 것입니다.
md 파일 스키마는 별도 문서(`weekly-report-md-schema.md`)를 참고하세요.

---

## 1. 배경 및 목표

- 현재 엑셀(`person.xlsm`, `part.xlsm`, `summary.xlsm`)로 주간업무보고를 작성 중이나, 양식이 깨지기 쉽고 데이터가 많으면 느려지는 문제가 있어 개선 필요
- 핵심 목표: **1인당 주간 단위 투입 공수(맨위크) 추적 관찰**
- 사용자는 팀 내 파트장(4명의 파트원 관리), 파트원 → 파트장 → 팀장으로 보고가 올라가는 구조

## 2. 조직/역할 구조

| 역할 | 인원 | 하는 일 |
|---|---|---|
| 파트원 | 4명 | 매주 본인 업무·투입공수 입력, md 내보내기 |
| 파트장 (본인) | 1명 | 파트원 md 취합, 본인 업무도 입력, 프로젝트/기타 요약 초안 자동생성 후 검토·편집 |
| 팀장 | 1명 | 파트장이 보낸 취합/요약 md를 업로드해 인물별 이력·프로젝트별 투입공수 조회 |

## 3. 인프라 결정사항

- **환경**: 폐쇄망(외부망 없음), 공유 서버/폴더 없음 → 모든 데이터 교환은 **`.md` 파일 + 메일 전달**
- **저장소**: 각 프로그램이 **로컬 H2**를 개별 소유 (교환용이 아니라 각자 데이터 저장 전용). md를 파싱해서 자기 DB에 적재
- **실행 방식**: Java/Spring Boot 내장 서버 + **fat jar + `.bat` 스크립트**로 실행 (`java -jar` 또는 콘솔 안 뜨는 `javaw`). `.exe`는 사내 보안 프로그램 승인 이슈로 배제. java/bat 실행은 전사 승인되어 있고 전원 자바 개발자라 문제 없음
- **개발 단계**: 1단계는 지금 이 로컬 프로그램 방식으로 개발, 이후 사내 서버 게시 허가가 나면 2단계로 웹서비스(로그인/RBAC 포함) 전환 예정. 데이터 모델은 최대한 재사용 가능하게 설계

## 4. 데이터 모델

### 4.1 일감(업무) 단위
- 두레이(협업툴) 방식을 반영: 회사명-팀명/일련번호 형식의 티켓번호 (예: `NHNKCP-개발1팀/117`)
  - 숫자만 입력하면 접두사(`NHNKCP-개발1팀`) 자동 완성
  - 접두사는 **설정 메뉴에서 변경 가능** (팀명이 바뀔 수 있음)
  - 접두사 변경 시 **과거 기록은 보존, 적용 시점 이후 입력분부터** 새 접두사 반영

### 4.2 투입공수(맨위크) 계산
```
맨위크 = (투입인원 × 일일투입시간 × 투입일수) / 5 / 8
       = (1 × hours × days) / 5 / 8   (본인 입력이므로 인원은 항상 1)
```
- 5 = 주당 업무일, 8 = 하루 기준 근무시간, 즉 **주 40시간 = 1.0 맨위크**
- 예: 하루 8시간 풀타임 1일 투입 = 0.2 맨위크
- 휴가도 맨위크 합산에 포함 (정상적으로 한 주 채우면 총합이 1.0에 가까워야 정상 신호)

### 4.3 그룹 구조 (최상위 4개, 순서 고정)
| 그룹 | 완료율 | 프로젝트 태그 | 비고 |
|---|---|---|---|
| 프로젝트 | 있음 | 있음(프로젝트명) | 프로젝트명은 수정 가능하며 수정 시 전체 이력에 반영. "종료" 기능 자리 확보(동작은 추후 정의) |
| 개발 | 있음 | 없음(미지정) | 소요시간이 작은 개별 업무 모음. "프로젝트로 이동" 기능으로 기존/신규 프로젝트에 편입 가능 |
| 기타 | 없음 | 없음 | 회의 등 반복성 업무 |
| 휴가 | 없음 | 없음 | 날짜 + 시간만 |

- 진행단계(구분): 프로젝트/개발 그룹 공통으로 **분석/설계 · 개발 · 테스트** 3단계
- 완료율: 0~100 숫자
- 일정 필드 3종(모두 선택): **개발완료일 / 테스트예정일 / 배포예정일**
- 비고: 자유서술 (주로 일정 변경 사유)
- **이월**: 완료율 100% 미만인 프로젝트·개발 그룹 항목은 다음 주로 자동 이월 (기타/휴가는 대상 아님)

### 4.4 필수값
- 프로젝트/개발 그룹: **티켓번호, 업무명, 완료율**만 필수 (시간·일수·일정·비고는 선택)
- 기타 그룹: 업무명 필수, 시간 선택
- 휴가 그룹: 날짜 필수, 시간 선택

### 4.5 주차 표기
- ISO 주차가 아니라 **`N월 M주차`** 형식 사용
- 주간보고 기준: **금요일 시작 ~ 목요일 종료**
- 계산 규칙: **그 주의 목요일이 속한 달**을 기준으로, 그 달의 몇 번째 목요일이 포함된 주인지로 `M주차` 결정
  - 예: `07.31(금)~08.06(목)`은 목요일이 8월이므로 **"8월 1주"**

## 5. 파트원(개인용) 화면 구성

### 5.1 온보딩 (최초 1회)
- 이름, 직책 입력 → 로컬에 저장 → 이후 재실행 시 생략

### 5.2 메인 대시보드
- 인사말 + 현재 주차 표시
- 이번 주 미작성 시 경고 배너 + "보고 작성" CTA 버튼
- 요약 지표: 최근 4주 평균 맨위크, 진행중 프로젝트 수
- 진행중인 프로젝트 목록 (완료율 progress bar, 종료 처리 전까지는 100%여도 계속 표시)
- 최근 이력 3개 미리보기 (전체 이력 화면 링크 포함)

### 5.3 등록(입력) 화면
- 레이아웃: **혼합형** — 상단 요약 카드(대시보드 스타일) + 세리프 헤더/모노스페이스 숫자/하단 이중선 합계(장부 스타일)
- 그룹(프로젝트/개발/기타/휴가)이 **탭 전환 없이 보고서처럼 세로로 나열**
- 프로젝트 그룹: 하위에 프로젝트별 소섹션 (이름 수정 가능 아이콘, "종료" 버튼 자리, "새 프로젝트 추가" 버튼)
- 개발 그룹 항목: "프로젝트로 이동" 아이콘 → 기존 프로젝트 선택 또는 신규 프로젝트 생성 → 선택 시 개발 그룹에서 제거되고 해당 프로젝트로 편입
- 등록 방식: **인라인**, 기본 한 줄(티켓번호·업무명·구분·시간·완료율) + 캘린더 아이콘 클릭 시 3개 일정 필드 + 비고란이 펼쳐지는 토글 방식
- 이월된 항목: 파란 `이월` 배지 표시
- 각 행에 **휴지통 아이콘**으로 삭제 가능

### 5.4 미리보기 & 내보내기
- 등록 완료 후 실제 저장될 문서 형태(장부 톤 유지) 그대로 읽기 전용 미리보기
- "수정하기"(뒤로가기) / "md로 내보내기"(확정) 버튼

### 5.5 이력 화면
- 별도 목록 화면 (대시보드와는 별개, 주차별 요약 행 전체 조회)
- 각 행: 주차 라벨 + 기간 + 총시간/맨위크, 클릭 시 그룹별 상세 확장
- 맨위크가 낮은 이상 주차는 색으로 강조(경고)
- **읽기 전용** (수정 불가 — 제출된 보고서는 고정)

## 6. 디자인 방향

- **톤**: 매주 반복 입력하는 실무 도구이므로 화려함보다 "빠르게 입력하고 한눈에 파악"이 우선
- **혼합 스타일**: 대시보드형 요약 카드(깔끔한 지표 카드, 넉넉한 여백) + 타임시트 원장형 디테일(세리프 헤더, 모노스페이스 숫자, 얇은 罫선, 합계 아래 이중선)
- 아이콘 기반 보조 액션(일정 추가, 프로젝트 이동, 삭제, 종료)으로 기본 화면은 압축하고 필요할 때만 펼치는 패턴을 일관되게 사용

## 7. 아직 정의되지 않아 파트장/팀장 화면 설계 시 함께 정리할 것

- 프로젝트 "종료" 버튼을 눌렀을 때의 실제 동작(집계/조회 화면 반영 방식)
- 종료된(완료된) 프로젝트를 조회하는 화면/위치
- 설정 화면(팀 접두사 변경) 상세 UI
- 파트장의 md 업로드 & 제출 현황 화면, 파트/요약 취합 로직 상세
- 팀장의 인물별 이력 조회 / 프로젝트별 집계 조회 화면
- 파트 취합본·팀장 요약본의 세부 md 스키마 (개인용 스키마를 기반으로 확장 예정)

## 8. 참고: 실제 분석한 기존 엑셀 구조 (설계 근거)

- `person.xlsm`: 대분류(사업계획/추가과제) > 프로젝트·과제명 > 주차 > 개별 일감 계층 구조, 계획/실적/차주계획이 한 줄에 공존, M/W(맨위크) 값 확인됨
- `part.xlsm`: person과 동일 스키마, 파트 전체 합산, 프로젝트를 분석/설계→구현→테스트/오픈 단계로 재배열
- `summary.xlsm`: 숫자표가 아닌 서술형 보고서. `# 프로젝트` / `# 기타` 섹션에 기능명+담당자+진행률%+주요일정 형태로 기록됨 → 이 형태를 자동 초안 생성의 목표 포맷으로 설정
