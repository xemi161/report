## 4. 확정된 설계 요지

상세 근거는 `_workspace/20260806_dashboard-redesign/design_summary.md`에 있다. 여기선 결론만 추린다.

### 4.1 사용자 확정 사항 (열린 질문 4건)

| # | 질문 | 결정 |
|---|------|------|
| 1 | 탭 구조 | **3탭(대시보드/작성/히스토리) 유지** — 히스토리를 대시보드에 흡수하는 2탭 안은 반려 |
| 2 | 이번 주 카드 CTA 라벨 | **상태별 라벨**(신규 작성 / 이어서 작성 / 수정하기) — 한 문구 고정 안은 반려 |
| 3 | 과거 보고서 목록에 초안 포함 | **반려 — 제출된(submitted) 보고서만** |
| 4 | 진행중인 프로젝트 카드 | **목록형**(프로젝트별 진행률 포함) — 숫자 하나짜리 통계 카드 안은 반려 |

### 4.2 화면 구성

- **IA**: `대시보드 · 작성 · 히스토리` 3탭, 기본 진입은 대시보드. 주차 페이저는 작성 탭에서만 노출한다
  (다른 탭에선 `visibility:hidden` — `display:none`이면 헤더 폭이 튀어 탭 전환 시 레이아웃이 흔들림).
- **이번 주 카드(hero)**: 사용자가 요청한 "신규작성 버튼"의 자리. 버튼만 있으면 *어느 주를 쓰는 건지*가 화면에 없어서
  카드로 감쌌다. 상태(미작성/작성중/제출됨)에 따라 배지와 버튼 라벨·스타일이 달라지고,
  "신규 작성"은 빈 상태 화면을 거치지 않고 즉시 이월 초안을 만들어 작성 화면으로 보낸다.
  **대시보드에서 accent 채움 `.btn`은 이 버튼 하나뿐** — 진한 버튼이 여러 개면 디자인 시스템의 위계가 깨진다.
- **최근 2주 평균 맨위크 카드**: 큰 숫자 + 구성 주차 나열(주차 라벨/맨위크/진행바). "최근 2주"가 어느 주인지
  화면에서 검증 가능해야 숫자를 신뢰할 수 있다는 이유로 내역을 함께 노출한다.
- **진행중인 프로젝트 카드**: 행마다 프로젝트명 + 일감번호 pill + 진행률 + 진행바 + 최근 보고 주차.
  진행률은 그 프로젝트 세부 항목 완료율의 **평균**(최댓값이 아님 — 설계 100% + 개발 20%를 100%로 보이면 안 됨).
- **과거 보고서 최근 5개**: 히스토리 탭의 `.hist-card`를 그대로 재사용하고 5건으로 자른다.
  목록 헤더 우측에 `전체 N개 보기 →`를 두어 히스토리 탭과의 관계를 명시(5개 이하면 렌더 안 함).
  카드 클릭 → 해당 주 **작성(수정)** 화면(읽기전용 상세 화면은 없음, 제출=비잠금 정책 그대로).
- **작성 탭 상단 통계 변경(부수 변경, ⚠️ 미실행)**: 기존 `최근 4주 평균 맨위크 / 진행중 프로젝트 수`를 대시보드 소유로
  옮기고 작성 탭은 "지금 보고 있는 주"의 `총 투입시간 / 맨위크 / 항목 수`로 바꾸자는 게 이 시점의 계획이었다.
  **실제 구현(2026-08-15)에서는 화면 구성 변경으로 스코프가 커진다는 이유로 이 교체를 하지 않았다** — 작성 탭은
  지금도 4주 평균 맨위크를 그대로 보여준다(다만 "진행중 프로젝트 수"는 대시보드와 같은 기준으로 통일됐다 —
  `EntryService.activeProjectsWithProgress()`, `_workspace/20260814_234652_dashboard-and-daily-notes-implementation/orchestrator_followup.md` 참고). 필요하면 별도 요청으로 처리.
- CSS는 기존 토큰만 사용했고 새 색 값은 추가하지 않았다. 이 시스템에 없던 유일한 새 형태는 5px 진행바.

### 4.3 3번 결정(제출본만)의 파급

목업의 `pastReports()` 필터 하나를 **대시보드 최근 5개 목록·히스토리 탭 목록·탭 라벨 건수·최근 2주 평균 맨위크
모집단·진행중 프로젝트 탐색 범위가 모두 공유**한다. 따라서 draft 제외 결정이 평균 맨위크의 모집단까지
"제출본이 존재하는 최근 2건"으로 자동으로 좁힌다 — 의도한 설계는 아니었지만 일관된 부수효과라 그대로 채택했다.
전부 제출본이므로 과거 보고서 카드에는 **상태 배지를 달지 않는다**(남는 배지는 "맨위크 낮음" 경고뿐).

### backend

- **최근 2주 평균 맨위크 계산 로직 신설**. 기존 `EntryService.recentAverageManWeek()`는 **4주** 기준이라 그대로 못 쓴다 —
  기간을 파라미터로 받게 고치거나(`recentAverageManWeek(int weeks)`) 2주용 메서드를 새로 만든다.
  모집단은 이번 주를 제외한 **제출된 최근 2건**(§4.3).
  - 손댈 곳: `src/main/java/com/weeklyreport/service/EntryService.java`(또는 `ManWeekService`)
- **"진행중인 프로젝트" 판정 기준 확정**. `Project.active`만으로 거를지, "active AND 최신 보고 진행률 < 100"으로 거를지
  결정이 필요하다(후자면 프로젝트별 최신 `ReportItem` 조회가 추가로 필요). 이 화면이 `Project.active`를
  **집계/필터링에 실제로 쓰는 첫 사례**이며, CLAUDE.md "다음에 할 일"의 기존 미결 항목
  "`Project.active` 집계/표시 방식 미정"이 이 결정으로 해소된다.
  - 손댈 곳: `src/main/java/com/weeklyreport/repository/ProjectRepository.java`, 대시보드용 서비스
- 대시보드 조회용 서비스/모델 구성. 과거 보고서 목록은 **기존 히스토리 조회(`status = submitted`)를 그대로 쓰고
  최근 5건 limit만 걸면 된다** — 새 필터 조건은 없다.

### frontend

- **`/`를 대시보드로 바꾸는 것이 이번 변경의 핵심.** 새 컨트롤러 + 새 템플릿이 필요하다
  (2026-08-02에 삭제한 `DashboardController`/`dashboard.html`의 복원이 아니라 새 설계).
  `/entry?week=...`·`/history`·`/history/{id}` 리다이렉트 관례는 그대로 둔다.
  - 손댈 곳: `src/main/java/com/weeklyreport/controller/`(신규 컨트롤러),
    `src/main/resources/templates/`(신규 템플릿), 탭 네비 프래그먼트(`fragments.html`)
- 목업의 대시보드 CSS 이식. 대시보드는 서버가 계산해 렌더하는 **거의 정적인 화면**이라
  htmx 배선이 사실상 필요 없다(링크 이동 + "신규 작성" 폼 전송 정도).
  목업 `<script>`의 상태 배열·`computeTotals`·`activeProjects` 같은 로직은 **이식하지 않는다** — 명세 시연용 장치다.
  - 손댈 곳: `src/main/resources/static/css/app.css`
- ⚠️ **작성 탭 통계 카드 교체 시 주의**: 새 통계(총 시간/맨위크/항목 수)는 인라인 편집마다 값이 달라져야 하는데,
  인라인 필드는 `hx-trigger="change" hx-swap="none"`이라 서버 재렌더가 없어 그대로 두면 값이 낡는다.
  완료율 100% "완료" 배지와 **같은 패턴으로 클라이언트 계산**을 넣어야 한다.
  (구조 변경 동작은 `#writeView`를 outerHTML로 통째 교체하므로 그때는 자동으로 맞는다.)
  - 손댈 곳: `src/main/resources/static/js/app.js`, `src/main/resources/templates/fragments-entry.html`
