# 주간 업무보고 MD 파일 스키마 (v2)

파트원이 입력화면에서 "md로 내보내기"를 누르면 생성되는 파일의 형식.
**사람이 읽는 마크다운 본문 하나로만 구성되며, 이 본문 자체가 파싱 가능한 고정 구조를 따른다.**
(v1에 있던 `<!--DATA ... DATA-->` JSON 블록은 2026-08-05자로 제거됨 — 아래 "v1과의 차이" 참고)

---

## 1. 파일명 규칙

```
주간보고_{이름}_{N월M주차}.md
예: 주간보고_정준호_8월1주.md
```

주차 라벨은 파일명에서만 공백을 뺀다(본문 제목에는 `8월 1주`처럼 공백 있는 형태를 쓴다).

## 2. 파일 전체 예시

```markdown
# 정준호 · 8월 1주

파트원 · 2026.07.31 (금) ~ 2026.08.06 (목)

## 프로젝트

### GTPP

- NHNKCP-개발1팀/23 : 외국환 보고서 현행화 [개발] — 8h · 3일 · 60%
  - 테스트예정일: 2026-08-10
  - 비고: 외부 연계사 일정으로 테스트 1주 연기

## 개발

- NHNKCP-개발1팀/26 : 2차인증 프로세스 개선 [설계] — 3h · 2일 · 5% (이월)

## 기타

- 파트 주간회의 — 1h
- 문의처리 — 1h

## 휴가

- 2026-08-03 — 8h

---

**합계: 40h / 1.00 맨위크**
```

주차는 금요일 시작 ~ 목요일 종료다(예시의 `2026.07.31 (금) ~ 2026.08.06 (목)`이 "8월 1주").

## 3. 파싱 규칙

파서는 이 본문의 고정 구조를 그대로 읽는다. 아래 규칙이 파트장/팀장 프로그램과의 **계약**이다.

### 3.1 문서 골격

| 줄 | 형식 | 설명 |
|---|---|---|
| 1행 | `# {이름} · {주차라벨}` | ` · `(공백 가운뎃점 공백)로 분리 |
| 2행 | `{역할} · {시작일} ~ {종료일}` | 날짜는 `yyyy.MM.dd (요일)` — **연도 포함**(v1은 연도가 없었음) |
| 그룹 | `## 프로젝트` / `## 개발` / `## 기타` / `## 휴가` | 순서 고정. 항목이 하나도 없는 그룹은 제목째로 생략됨 |
| 프로젝트 소제목 | `### {프로젝트명}` | `## 프로젝트` 아래에만 존재. 프로젝트 여러 개면 소제목도 여러 개 |
| 합계 | `---` 다음 줄에 `**합계: {시간}h / {맨위크} 맨위크**` | 파일 마지막 |

- **`group` 필드는 별도 표기가 없다** — 그 줄이 어느 `##` 제목 아래에 있는지로 결정한다.
- **`project` 필드도 별도 표기가 없다** — `## 프로젝트` 안에서 직전 `### 소제목`이 그 항목의 프로젝트명이다.

### 3.2 항목 줄 문법 — 프로젝트 / 개발 그룹

```
- {티켓 : }{제목}{ [구분]} — {시간}h · {일수}일 · {완료율}%{ (이월)}
```

- 티켓이 없으면 `{티켓} : ` 부분이 통째로 빠진다 (`- 사내 위키 정리 [개발] — 2h · 1일 · 100%`).
- 구분이 없으면 `[...]` 부분이 통째로 빠진다.
- 시간이 없으면 `{시간}h · ` 부분이 통째로 빠져 `— 1일 · 60%`로 시작한다.
- **일수는 절대 생략되지 않는다** — 미입력이면 `1일`로 채워 나간다. 즉 이 자리에 `{숫자}일`이 없으면 규격 위반(파싱 불가)으로 취급한다.
- 완료율도 항상 있다(미입력이면 `0%`).
- 이월 항목이면 줄 끝에 ` (이월)`이 붙는다.

**구분자 정리**: 티켓/제목은 ` : `(공백-콜론-공백), 제목 블록과 수치 블록은 ` — `(공백-em dash U+2014-공백), 수치 세그먼트끼리는 ` · `(공백-가운뎃점 U+00B7-공백).

**파서 구현 팁**: 제목에 콜론이나 대시가 들어갈 수 있으므로, 티켓은 **첫 번째** ` : `로, 수치 블록은 **마지막** ` — `로 자르는 편이 안전하다.

### 3.3 항목 줄 문법 — 기타 / 휴가 그룹

```
- {제목 또는 날짜}{ — {시간}h}
```

- 구분·일수·완료율·이월 표기가 없다.
- 시간이 없으면 ` — {시간}h`가 통째로 빠진다.
- 휴가는 제목 자리에 날짜가 온다: 하루면 `- 2026-08-03`, 기간이면 `- 2026-08-05 ~ 2026-08-06`. **ISO 형식(`yyyy-MM-dd`)이며 연도를 포함**한다(헤더 날짜와 형식이 다르니 주의).
- 기간 휴가의 시간은 기간 전체 합산치 하나만 쓴다(일별로 항목을 쪼개지 않는다).

### 3.4 하위 불릿 — 일정 / 비고

항목 줄 **바로 아래**에 공백 2칸으로 들여쓴 불릿으로 붙는다. 값이 없는 필드는 줄 자체가 나오지 않는다.

```
  - 개발완료일: 2026-08-08
  - 테스트예정일: 2026-08-10
  - 배포예정일: 2026-08-14
  - 비고: 외부 연계사 일정으로 테스트 1주 연기
```

- 라벨(`개발완료일` / `테스트예정일` / `배포예정일` / `비고`)로 필드를 식별한다. 순서는 항상 위 순서이나 중간 누락이 있을 수 있으므로 **라벨 기준으로 찾는다**.
- 날짜 3종은 ISO 형식(`yyyy-MM-dd`), 비고는 자유 텍스트.

### 3.5 필드 추출 표

| 필드 | 그룹 | 마크다운에서의 추출 위치 | 필수 |
|---|---|---|---|
| `group` | 전체 | 상위 `##` 제목: `프로젝트`→project, `개발`→dev, `기타`→etc, `휴가`→vacation | 필수(구조로 결정) |
| `project` | project | `## 프로젝트` 아래 직전 `### {프로젝트명}` 소제목 | 필수(project만). 다른 그룹엔 소제목 자체가 없음 |
| `ticket` | project, dev | `- ` 뒤부터 첫 ` : ` 앞까지. ` : `가 없으면 티켓 없음 | 아래 검증 규칙 참고 |
| `title` | 전체 | ` : ` 뒤(티켓 없으면 `- ` 바로 뒤)부터 ` [`(구분 있을 때) 또는 마지막 ` — `(구분 없을 때) 앞까지 | 필수. vacation은 날짜가 이 자리를 차지 |
| `phase` | project, dev | 제목 뒤 `[...]` 안의 짧은 라벨 | 선택. 없으면 대괄호째 생략 |
| `hours` | 전체 | ` — ` 뒤 첫 `{숫자}h` 세그먼트 | 선택. 없으면 세그먼트째 생략 |
| `days` | project, dev | `{숫자}일` 세그먼트 | **항상 표기됨**(미입력 시 `1일`). 없으면 파싱 불가 |
| `completion` | project, dev | 마지막 `{숫자}%` 세그먼트 | **항상 표기됨**(미입력 시 `0%`) |
| `carriedOver` | project, dev | 줄 끝 ` (이월)` 문자열의 존재 여부 | 선택(없으면 false) |
| `devDoneDate` | project, dev | 하위 불릿 `  - 개발완료일: {ISO 날짜}` | 선택. 줄이 없으면 값 없음 |
| `testDate` | project, dev | 하위 불릿 `  - 테스트예정일: {ISO 날짜}` | 선택. 줄이 없으면 값 없음 |
| `deployDate` | project, dev | 하위 불릿 `  - 배포예정일: {ISO 날짜}` | 선택. 줄이 없으면 값 없음 |
| `note` | project, dev | 하위 불릿 `  - 비고: {자유 텍스트}` | 선택. 줄이 없으면 값 없음 |
| `date` | vacation | `- {ISO 날짜}` (기간이면 ` ~ ` 앞부분) | 필수(vacation만) |
| `endDate` | vacation | `- {날짜} ~ {날짜}`의 ` ~ ` 뒷부분 | 선택. ` ~ `가 없으면 하루짜리 휴가 |
| 이름 / 역할 / 주차라벨 / 주차 기간 | 문서 | 1~2행 헤더 | 필수 |
| 합계 시간 / 합계 맨위크 | 문서 | 마지막 `**합계: ...**` 줄 | 필수(항목에서 재계산 가능하므로 검증용) |

**`phase` 표기 주의**: 본문 대괄호에는 **짧은 라벨**이 들어간다. 내부 값과 1:1로 매핑된다.

| 본문 표기 | 내부 값 |
|---|---|
| `[설계]` | 분석/설계 |
| `[개발]` | 개발 |
| `[테스트]` | 테스트 |

즉 `분석/설계`는 본문에 `[설계]`로 나가므로, 파서는 `[설계]` → `분석/설계`로 되돌려 읽어야 한다.

### 3.6 필수값 검증 규칙

- project/dev 그룹: 티켓번호, 업무명, 완료율만 필수. 시간·일수·일정·비고는 선택
  - ⚠️ dev 그룹의 티켓 필수 여부는 **아직 미결**이다(CLAUDE.md "다음에 할 일" 참고). 마크다운 문법 자체는 티켓 없는 줄을 지원하므로, 파서는 티켓 없는 dev 줄을 만나도 죽지 않게 만들 것.
- etc 그룹: 업무명 필수, 시간 선택
- vacation 그룹: 날짜(`date`) 필수, `endDate`·시간 선택. `endDate`가 있으면 기간 휴가 — 일별로 항목을 쪼개지 않고 한 항목(`hours`는 기간 전체 합산치)으로 유지

### 3.7 맨위크 계산

```
항목 맨위크 = (hours × days) / 40      // days 미표기는 규격 위반, 표기상 최소 1일
합계 맨위크 = Σ(hours × days) / 40     // 소수점 2자리 반올림
합계 시간   = Σ(hours × days)
```

합계 줄의 시간은 `hours` 단순합이 아니라 **`hours × days`의 합**이다(예시: 8×3 + 3×2 + 1 + 1 + 8 = 40h).

## 4. v1과의 차이 (2026-08-05)

- `<!--DATA ... DATA-->` JSON 블록 **완전 제거**. 파싱 대상은 마크다운 본문 그 자체다.
- project/dev 항목 줄에 **일수(`{숫자}일`)가 항상 표기**된다(v1은 시간·완료율만 있었음).
- 헤더 2행 날짜에 **연도가 포함**된다(v1: `08.01 (금)` → v2: `2026.08.01 (금)`).

> **v1 하위호환 결정 (2026-08-05)**: v1 형식(JSON 블록 포함)으로 내보낸 과거 파일은 지원하지 않는다. 파트장 프로그램이 아직 미개발이라 실사용 v1 파일이 사실상 없고, 하위호환을 위해 파서가 두 형식을 모두 다뤄야 하는 복잡도를 감수할 이유가 없기 때문이다. 파서는 v2(마크다운 전용) 형식만 가정하고 구현한다.

## 5. 파트장/팀장 프로그램에서의 처리

- 파트장 프로그램은 이 마크다운 본문의 고정 구조(그룹 순서, 줄 문법)를 파싱해서 자기 로컬 H2에 저장한다. 사람이 읽는 본문과 파싱 대상이 **같은 텍스트**이므로, 본문 포맷을 바꾸면 곧 계약이 깨진다 — `MdExportService`를 고칠 때 반드시 이 문서를 함께 갱신할 것.
- 파트장이 내보내는 파트 취합본 / 팀장이 받는 요약본도 동일한 파일명·구조 원칙(마크다운 본문 하나)을 따르되, 상세 스키마는 파트장 화면 설계 시 별도 정의한다.
