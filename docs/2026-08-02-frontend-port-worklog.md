## 1. 목업 단계에서 확정한 변경

### 1.1 프로젝트 카드 = 일감(티켓) 하나

기존 목업은 `프로젝트 → 일감 여러 개 → 각 일감의 세부 항목` 3단 구조였다. 이걸 **`프로젝트(=일감 하나) → 세부 항목`** 2단으로 줄였다.

- 근거: 일감 블록의 "제목" 필드가 실제로는 프로젝트명과 항상 같은 값이라 중복이었고, 사용자 워크플로상 프로젝트 하나당 일감도 정확히 하나였다.
- 카드 헤더는 **일감번호 → 프로젝트명** 순서(일감번호를 먼저 읽는 게 자연스럽다는 피드백). "+ 일감 추가" 버튼은 삭제.
- 세부 항목은 그대로 "그때그때 추가" 방식이고, 같은 구분(예: 개발)을 여러 개 넣을 수 있다.
- **데이터 스키마 변경 아님** — md에는 여전히 세부 항목마다 `- {티켓} : {제목} [구분] — {시간}h · {완료율}%` 한 줄씩 나간다.

### 1.2 휴가: 하루 / 기간

휴가를 하루로도 기간으로도 쓸 수 있어야 한다는 요구로, 행마다 **"하루로 / 기간으로" 토글**을 넣었다.

- 기간이면 `시작일 ~ 종료일`을 입력하고 시간은 기간 전체 합산치를 직접 넣는다(일별로 항목을 쪼개지 않음).
- md 스키마에 `endDate`(vacation, 선택)를 추가하고 본문 표기 규칙도 갱신했다.

### 1.3 미니멀 SaaS 방향 리스타일

기능은 그대로 두고 시각만 다듬었다. 라운드 확대(14~16px → 18~20px), 보더를 옅게, 여백 확대, 카드 hover 시 은은한 그림자, "+ 항목 추가"를 점선 박스에서 플랫 텍스트 버튼으로, 토글은 알약 모양. 색(단일 블루 accent, 라이트 톤 고정)은 유지.

### 1.4 이 과정에서 잡은 버그 2개

- **md 제목 폴백이 동작하지 않던 문제**: `{ title: i.title || p.name, ...i }` 순서라 뒤의 `...i`가 빈 title로 덮어써서, 제목 없는 세부 항목이 "(제목 없음)"으로 나갔다. 스프레드 순서를 뒤집어 수정.
- **일정 입력칸 스타일 불일치**: 휴가 날짜 입력을 고치려 넣은 `.row input[type=date]` 규칙이 명시도 때문에 `.row-detail`(개발완료일/테스트예정일/배포예정일 패널)까지 침범해, 같은 패널 안 "비고"와 테두리·패딩이 미묘하게 달라졌다. 리셋 범위를 `.row-main`/`.simple-row`로 좁혀 `.row-detail`과 절대 겹치지 않게 분리.

## 2. 실제 앱 이식

### 2.1 화면/라우팅

3화면(대시보드·등록·이력) → **2탭(작성·히스토리)**.

- 삭제: `DashboardController`, `dashboard.html`, `history-detail.html`, `preview.html`, `PreviewExportController`(→ `ExportController`로 정리)
- `/`·`/entry?week=yyyy-MM-dd` = 작성, `/history` = 히스토리, `/export/{id}` = md 다운로드
- `/history/{id}`는 옛 링크 호환용으로 해당 주 작성 화면으로 리다이렉트
- 주차 이동·탭 전환은 평범한 링크(전체 페이지 로드), 나머지 조작만 htmx
- **주차를 넘겨봐도 보고서를 자동 생성하지 않는다** — 없는 주는 빈 상태 화면이고, "작성 시작"을 눌러야 이월 포함 초안이 생긴다. (빈 보고서가 줄줄이 생기는 걸 막고, 목업의 빈 상태 화면과도 일치)

### 2.2 도메인

- `Project.ticket` 추가. 프로젝트 항목 저장 시 이 값을 `ReportItem.ticket`으로 복사한다 — md 스키마(항목 1개 = 줄 1개)는 건드리지 않으면서 화면에서는 카드 헤더 한 곳에서만 티켓을 관리하기 위함. 과거 주의 티켓은 그때 복사된 값 그대로 남는다.
- `ReportItem.endDate` 추가(휴가 기간). `isPeriodVacation()`은 `endDate != null`로 판정 — 별도 플래그 컬럼을 두지 않았다.
- `ReportItem.displayTitle()`: 프로젝트 세부 항목의 제목이 비면 프로젝트명으로 대체. md 본문·JSON·검증이 모두 이걸 쓴다.
- 표기용 헬퍼 `hoursDisplay()` / `totalHoursDisplay()`: DB에서 `8.00`으로 돌아오는 BigDecimal이 좁은 입력칸에서 잘려서, 뒷자리 0을 떼어 `8`로 보이게 한다.

### 2.3 정책 변경 — 제출된 보고서도 계속 수정 가능

사용자 요구에 따라 `WeeklyReport.status`는 **잠금이 아니라 상태 표시**로만 쓴다.

- `EntryService.requireEditable()` 제거 → 제출된 주도 항목 추가/수정/삭제 및 재제출("다시 내보내기") 가능
- `HistoryController`의 읽기전용 상세 화면 제거
- ⚠️ `project-handoff-summary.md`의 "제출된 보고서는 고정" 규칙은 이 결정으로 **폐기**됨. 그 문서는 아직 옛 규칙을 담고 있으니 주의.

### 2.4 htmx 배선 규약

폐쇄망이라 CDN을 못 쓰므로 `static/js/htmx.min.js`(2.0.4)를 저장소에 직접 넣었다.

- **구조가 바뀌는 동작**(항목 추가/삭제, 휴가 기간 토글, 프로젝트 추가/삭제)은 `#writeView` **전체**를 다시 렌더링해 `hx-swap="outerHTML"`로 교체. 카드별 건수·통계·빈 상태가 한 번에 맞아떨어져서, 프래그먼트를 잘게 쪼개 각각 갱신하는 것보다 안전하고 단순하다.
- **인라인 필드 수정**은 `hx-trigger="change" hx-swap="none"` — 화면을 다시 그리면 입력 포커스가 날아가므로 저장만 한다. 그래서 완료율 100% "완료" 배지는 `static/js/app.js`가 클라이언트에서 즉시 붙인다(일정 패널 접기/펴기, 토스트, 모달 닫기도 여기).
- 행 하나가 통째로 `<form>`이고, `week`는 전부 **쿼리스트링**으로 넘긴다 — 버튼이 폼 안에 있든 밖에 있든 동일하게 전달되기 때문.
- "md로 내보내기"만 htmx가 아닌 일반 폼 전송. 응답이 첨부파일이라 브라우저가 직접 받아야 한다.

## 3. 밟은 함정 (재발 방지)

1. **Thymeleaf는 `th:replace`를 `th:each`/`th:if`보다 먼저 처리한다.**
   같은 태그에 같이 쓰면 반복/조건이 적용되기 전에 프래그먼트가 불려서 인자가 null로 들어가고
   `EL1007E: Property or field 'id' cannot be found on null`이 난다.
   → 반드시 바깥 `<th:block th:each>` + 안쪽 `<div th:replace>`로 나눌 것.
2. **`th:text`를 바깥 div에 걸면 안쪽 자식이 지워진다.** 주차 라벨의 `.range` span이 통째로 사라졌다.
3. **`./gradlew bootRun`은 `build/resources/main`을 읽는다.** 실행 중에 `src/main/resources`의 템플릿을 고쳐도 반영되지 않으므로 재시작이 필요하다. `thymeleaf.cache=false`만 믿고 헤매지 말 것.

## 4. 검증

`./gradlew build` 통과(단위 테스트 포함). 추가한 테스트:

- 기간 휴가가 md 본문에 `2026-08-05 ~ 2026-08-06 — 16h`로, JSON에 `endDate`로 나가는지
- 프로젝트 세부 항목 제목이 비면 프로젝트명으로 대체되는지

그리고 실제로 앱을 띄워 Playwright로 브라우저에서 아래 경로를 직접 확인했다.

온보딩 → 빈 상태에서 초안 생성 → 티켓번호 자동완성(`23` → `NHNKCP-개발1팀/23`) → 세부 항목 인라인 저장 → 일정·비고 패널 → 완료 배지 즉시 반영 → 개발/기타 항목 → 휴가 하루/기간 토글 → 미리보기 모달 → md 다운로드(`주간보고_정준호_8월1주.md`) → 제출 상태 배너 및 재편집 → 히스토리 목록/카드 클릭 → 다음 주 이동 → 이월 초안 생성(100% 완료 항목은 제외되는지 확인) → 필수값 누락 시 내보내기 차단 → 항목·프로젝트 삭제.

콘솔 에러 없음.

## 5. 남은 것 / 열린 질문

- **개발 그룹의 티켓번호 필수 여부** — `weekly-report-md-schema.md`의 검증 규칙("project/dev 그룹은 티켓번호 필수")을 그대로 구현해서, 지금은 티켓 없으면 제출이 막힌다. 그런데 승인된 목업 샘플에는 티켓 없는 개발 항목("사내 위키 정리")이 있었고 md 포맷 자체도 티켓 없는 줄을 지원한다. 개발 그룹은 티켓을 선택으로 풀지 결정 필요.
- 파트장/팀장 화면은 여전히 범위 밖(파트원 화면만 확정).
- `Project.active`(프로젝트 "종료") 플래그는 카드 삭제 시 비활성 처리에만 쓰고 있고, 종료된 프로젝트의 집계/조회 반영 방식은 아직 미정.
- `project-handoff-summary.md`가 옛 "제출 후 고정" 규칙을 담고 있어 현재 동작과 어긋난다 — 손볼지 결정 필요.
