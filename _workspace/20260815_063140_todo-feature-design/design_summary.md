## 1. 배치

우측 스택(`.dash-side`) **맨 위**, 맨위크 카드보다 위. 스택 순서는
`앞으로 할 일 → 최근 2주 평균 맨위크 → 진행중인 프로젝트`.

- 4번째 탭 신설·히스토리 편입·좌측 회고 카드 옆 배치는 검토 문서에서 이미 기각된 안이라 재검토하지 않았다.
- 스택 내 순서를 맨 위로 잡은 이유: 아래 두 카드는 주 단위로만 훑는 **참조 지표**인데 할 일은 **매일 손대는 조작 대상**이다. hero(이번 주 카드) 다음으로 눈이 가는 자리에 있어야 스크롤 없이 체크할 수 있다.
- 부작용 보정: 우측 스택이 길어져 좌측 "오늘 한 일" 카드(`align-items:stretch`로 스택 높이만큼 늘어남) 아래가 빈 여백이 된다 → `DASH_RECENT_DAYS` 4 → 5로 올려 실제 내용으로 채웠다.

## 2. 어휘 (검증 기준)

- 카드 제목 = **"앞으로 할 일"**. 항목은 "할 일", 기한은 "기한".
- **"기록"이라는 단어를 이 카드 안에서 한 번도 쓰지 않는다** — 회고형 DailyNote 전용 어휘.
- "할 일" 단독으로 쓰지 않고 "앞으로"를 붙인 이유: 좌측 카드가 "오늘 한 일"이라 **한 일 / 할 일이 한 글자 차이**다. 첫 단어(오늘 / 앞으로)부터 갈라야 스캔할 때 안 겹친다.
  - 사용자가 "할 일" 또는 "예정"으로 짧게 가길 원하면 제목만 바꾸면 되고 나머지 문구는 영향 없다.
- 카드 하단 고정 문구: `개인용 목록입니다. 주간보고(.md)에는 나가지 않습니다.` — 좌측 패널의 `.daily-note`(기록이 항목으로 자동 안 옮겨진다) 와 같은 자리·같은 스타일. .md 미포함이라는 확정 스코프를 화면이 스스로 못박게 했다.
- 시간 관련 라벨 없음(예상소요시간 필드가 스코프에 없으므로 "기록된 시간"과 혼동될 지점이 아예 생기지 않는다).

## 3. 화면 구조

```
┌ 앞으로 할 일        [5건]        ← count 칩 = 미완료 건수
│ [기한 date][보통][할 일 추가 (Enter)]   ← .quick-add (좌측 카드와 동일 컴포넌트)
│ 기한 지남                    2건  ← .day-head.over (danger)
│   ☐ [08.10] GTPP 결제 타임아웃…  [높음] 📅 🗑
│   ☐ [08.12] 2차인증 API 스펙 회신 [보통] 📅 🗑
│ 08.13 (목) [오늘]
│   ☐ 결제 배치 재처리 결과 확인    [높음] 📅 🗑
│ 08.14 (금)
│   ☐ OTP 발송 모듈 코드리뷰 반영   [보통] 📅 🗑
│ +1건 더 보기 →
│ ─────────────
│ 완료 2건 보기                    ← 기본 접힘
│ 개인용 목록입니다. 주간보고(.md)에는 나가지 않습니다.
```

### 날짜를 그룹 헤더가 받는 이유
우측 스택 카드는 폭 320px, 카드 패딩 제외 **내부 264px**다. 행마다 날짜를 반복하면 텍스트에 남는 폭이 없다.
그래서 좌측 기록 패널이 이미 쓰는 `.day-group` / `.day-head`(날짜 헤더 + 그 아래 항목들)를 **그대로 재사용**했다 — 새 컴포넌트가 아니라 이 시스템에 이미 있는 "날짜 머리를 단 목록"이다.

### 기한 지남 표시 (자동 이월 없음의 시각적 대응)
- 기한이 지난 항목만 **한 그룹으로 묶고** 헤더를 `기한 지남 · N건`, 색은 `--danger-fg`.
- 이 그룹은 항목마다 날짜가 다르므로 **이 그룹에서만** 행 앞에 날짜 칩(`--danger-bg`/`--danger-fg`, 예 `08.10`)을 붙인다. "얼마나 밀렸나"가 항목마다 다른 정보인 곳이 여기뿐이다.
- 날짜는 프로그램이 옮기지 않는다(확정 스코프). 옮기는 건 사람이 📅 버튼으로 직접 한다.

### 우선순위
- 3단계 `높음 / 보통 / 낮음`, 기본 **보통**.
- **표시와 편집을 한 컨트롤이 겸한다** — pill 버튼을 누르면 높음→보통→낮음 순환. 좁은 카드에 셀렉트를 따로 두지 않기 위한 선택.
- 색: **높음만** `--warn-bg`/`--warn-fg`(주황). 보통은 `--text-muted`, 낮음은 `--text-faint`로 배경 없이 조용하게. 기본값에서 벗어난 것만 색이 붙어야 목록이 배지밭이 되지 않는다.
- 새 색 토큰 없음. 주황은 작성 화면의 "이월" 배지와 같은 토큰이지만 **다른 화면·다른 라벨**이라 혼동 지점이 아니다(할 일 카드에는 이월 배지가 존재하지 않는다).
- 정렬: 기한 이른 순 → 우선순위(높음·보통·낮음) → 등록순. 기한 지난 것이 자동으로 맨 위로 온다.

### 기한 변경
행을 한 줄로 유지하려고 📅 버튼 → 아래로 펼쳐지는 `.row-detail`(보고 항목의 일정 상세 패널과 **같은 컴포넌트**) 안에 `기한` date 입력 하나. 자주 하는 조작이 아니므로 상시 노출하지 않는다.

### 완료 항목 정리 (요구 3에 대한 결정)
- 체크하면 **날짜 그룹에서 빠져** 카드 맨 아래 `완료 N건 보기` 섹션으로 내려간다. 그 섹션은 **기본 접힘**.
- 펼치면 취소선 + `--text-faint`로 표시되고 체크를 풀어 되돌릴 수 있다.
- 자동 삭제·자동 만료 없음. 삭제는 항상 사용자가 🗑으로 한다.
- 근거: 264px 카드에서 남은 일이 주인공이어야 한다. 그렇다고 지워버리면 "잘못 체크했다"를 되돌릴 방법이 사라진다 → 한 클릭 뒤에 둔다.

### 넘칠 때 (요구 4에 대한 결정)
- 미완료 **6건**까지 펼쳐 보이고, 그 이상은 `+N건 더 보기 →`(`.link-more`)로 **이 카드 안에서 그 자리에 펼친다**. 펼치면 `접기`로 바뀐다.
- 전체 열람 화면을 만들지 않은 이유: 이번 스코프에 없고, 링크를 걸 곳도 없다. 다른 화면으로 보내는 대신 카드가 스스로 길어지는 쪽이 IA를 건드리지 않는다.

## 4. 재사용/신규 정리

| 재사용한 기존 컴포넌트 | 용도 |
|---|---|
| `.card` / `.card-head` / `.card-title` / `.count` | 카드 껍데기, 미완료 건수 칩 |
| `.day-group` / `.day-head` / `.today-chip` | 기한별 그룹 헤더, "오늘" 칩 |
| `.quick-add` + `.date-sel` | 추가 입력줄(좌측 기록 카드와 동일 — "여기 입력한다"가 먼저 읽혀야 하는 캡처 지점 예외 규칙 그대로) |
| `.row-detail` / `.icon-btn` / `.icon-btn.chevron` | 기한 변경 접이식 패널, 삭제/달력 버튼 |
| `.link-more` | 더 보기 / 완료 보기 |
| `.d-txt` 규칙 | 할 일 텍스트(`.t-txt`) — 평소 텍스트, hover/focus 시 강조 + 줄바꿈 textarea |

신규 클래스는 `.todo-row .todo-item .t-wrap .t-txt .od .prio .todo-foot .todo-done .todo-note` 뿐이고 **전부 기존 토큰/스케일만 사용**한다. 새 oklch 값 없음, 다크모드 관련 코드 없음.

## 5. QA 검증 가능한 기준

1. 대시보드 우측 스택 첫 카드가 "앞으로 할 일"이다(맨위크 카드보다 위).
2. 카드 어디에도 "기록"이라는 단어가 없다.
3. count 칩 = **미완료** 건수(완료 포함 아님).
4. 기한 < 오늘인 항목은 `기한 지남` 그룹에 모이고 헤더가 `--danger-fg`, 각 행 앞에 danger 색 날짜 칩이 붙는다. 오늘/미래 그룹에는 날짜 칩이 없다.
5. 우선순위 pill: 높음만 주황(`--warn-bg`/`--warn-fg`), 보통/낮음은 배경 없음. 클릭하면 높음→보통→낮음 순환.
6. 완료 체크 시 항목이 날짜 그룹에서 사라지고 하단 `완료 N건 보기`로 이동, 펼치면 취소선.
7. 미완료 7건 이상이면 `+N건 더 보기` 노출, 클릭하면 같은 카드 안에서 펼쳐짐.
8. 이 기능은 `.md` 미리보기/내보내기 결과에 **한 줄도 나타나지 않는다**.
9. 일일 기록(DAILY)과 서로 이동/승격하는 동작이 **없다**.

## 6. frontend에게 넘길 때의 경계 (승인 후)

- 시각 스타일·정보구조·문구는 목업 그대로. **`<script>`의 상태 배열/이벤트 위임 로직은 이식하지 않는다** — 서버 렌더링 + htmx로 대체한다.
- 구조가 바뀌는 조작(완료 체크, 우선순위 변경, 기한 변경, 추가, 삭제)은 이 프로젝트 규약대로 **카드 프래그먼트를 통째로 다시 렌더링**하는 쪽이 맞다(그룹 소속·건수·"+N건 더"가 한 번에 맞아야 한다). 목업이 `renderDashboard()`를 다시 부르는 것도 같은 이유다.
- 텍스트 인라인 수정만 `hx-trigger="change" hx-swap="none"`(포커스 유지). 목업도 텍스트 입력에서만 재렌더링을 하지 않는다.
- 펼침 상태(`+N건 더`, `완료 N건`)는 서버 상태가 아니라 화면 상태다 — 목업은 모듈 변수로 들고 있고, 실제 앱에서는 쿼리 파라미터나 app.js 클라이언트 토글 중 frontend가 판단할 몫이다.

## 7. 사용자 확인이 필요한 지점

1. 카드 제목 **"앞으로 할 일"**(vs 짧은 "할 일" / "예정") — 좌측 "오늘 한 일"과의 혼동을 피하려는 선택.
2. 우선순위 **3단계**(높음/보통/낮음)와 "pill을 눌러 순환" 방식.
3. 완료 항목을 **하단 접힌 섹션**에 남기는 방식(숨김/취소선 유지/삭제 중 택1의 결론).
4. 접힌 상태에서 보여줄 항목 수 **6건**.
