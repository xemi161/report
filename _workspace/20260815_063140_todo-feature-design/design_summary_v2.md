## 1. 왜 벤토 그리드로 바꿨나

v6까지 대시보드는 `hero 한 줄 + 좌우 2컬럼 스택`이었다. 사용자 피드백은 **"눈에 탁 띄지 않고 참신하지 않다"**였고, 원인을 배치에서 찾았다:

1. **모든 카드가 사실상 같은 크기**였다. hero는 가로로만 길고 높이가 낮았고, 우측 스택 카드 3개는 폭이 전부 320px로 동일했다. 화면이 "균일한 격자"로 읽히니 **무엇이 중요한지를 레이아웃이 말해주지 못했다.**
2. hero가 숫자(시간/맨위크/건수)를 붙들고 있어서, 나머지 카드는 전부 "목록형 카드"뿐이었다 — 리듬을 만들 요소가 없었다.
3. 카드 간격 22px + 카드 패딩 26/28px로 **밀도가 낮아** 화면이 헐거웠다.

그래서 v7은 같은 정보를 **크기가 엇갈리는 모자이크**로 다시 깐다. 참신함의 출처를 다음 셋으로 한정했다(사용자가 못박은 제약: 색이나 다크테마로 만들지 말 것):

- **면적 차이** — 6×4 큰 타일 옆에 3×2 작은 타일 4개, 아래는 8×6과 4×10의 비대칭
- **밀도** — gap 22 → **14px**, 카드 패딩 26/28 → **20/22px**(지표 타일은 16/18)
- **거대 숫자** — 작은 타일 안의 **40px 숫자**(좁은 면적 × 큰 숫자의 대비)

**지키지 않은 것은 없다**: 다크모드 코드 없음(`:root[data-theme]` 고정 블록 그대로), 새 oklch 토큰 0개, 연회색 배경 + 흰 카드 + 얇은 보더 + 18px 라운드 그대로. 색은 기존 `--accent` / `--accent-soft` / `--danger-fg` / `--surface-sunken`만 쓴다.

## 2. 확정 구도 (뷰포트 > 1180px)

12컬럼 × **62px 고정 행**, gap 14px. 고정 행이어야 "4행짜리 큰 타일 옆에 2행짜리 작은 타일 둘"처럼 **행을 쪼개 쓰는** 배치가 가능하다(행 높이가 내용에 따라 늘면 모자이크가 무너진다).

```
┌──────────────────────┬───────────┬───────────┐
│                      │ 이번 주    │ 이번 주    │
│  이번 주 (6×4)        │ 시간 32h  │ 맨위크 .80 │  ← 지표 타일 3×2
│  8월 2주 · 상태 · CTA  ├───────────┼───────────┤
│  + 요일별 기록 스트립   │ 기한지남 2 │ 진행중 3   │
├──────────────────────┴────┬──────┴───────────┤
│  오늘 한 일 (8×6)           │                  │
│                           │  TODO 리스트      │
├─────────────┬─────────────┤  (4×10)          │
│ 최근 2주     │ 진행중       │                  │
│ 맨위크 (4×4) │ 프로젝트(4×4)│                  │
└─────────────┴─────────────┴──────────────────┘
┌──────────────────────────────────────────────┐
│  과거 보고서 (12×auto)                         │
└──────────────────────────────────────────────┘
```

좌측 덩어리 6+4=10행, 우측 TODO 10행 → **두 덩어리가 같은 줄에서 끝난다**(어느 쪽도 빈 꼬리를 남기지 않는다).

⚠️ 배치는 `grid-auto-flow`(sparse)에 맡겼다. **DOM에 넣는 순서가 곧 배치**다: `hero → 지표4 → 오늘 한 일 → TODO → 맨위크 → 진행중`. 순서를 바꾸면 구도가 무너진다(`.bento` CSS 주석에 행/열 계산 전부 기록해둠).

## 3. 타일 크기 배정 기준

**크기 = 손대는 빈도.** 정보량이 아니라 사용 빈도를 기준으로 잡았다(정보량 기준으로 잡으면 TODO보다 과거 보고서가 커진다).

| 타일 | 크기 | 실치수 | 배정 근거 |
|---|---|---|---|
| 이번 주(hero) | 6×4 | 535×290 | 화면의 목적("지금 뭘 해야 하나")이자 **유일한 강한 CTA**(accent `.btn`은 화면에 하나만) |
| 오늘 한 일 | 8×6 | 718×442 | **매일 여러 번** 타이핑하는 캡처 지점 — 가장 넓은 폭이 필요 |
| TODO 리스트 | 4×10 | 352×746 | 매일 손대지만 **세로로 긴 목록** — 폭보다 길이가 필요 |
| 최근 2주 맨위크 / 진행중 프로젝트 | 4×4 | 352×290 | **주 단위로만** 훑는 참조 지표 — 중간 크기 |
| 지표 4개 | 3×2 | 260×138 | 한 번 쳐다보고 마는 숫자 — 가장 작게, 대신 숫자를 40px로 |
| 과거 보고서 | 12×auto | 전폭 | 모자이크를 받치는 바닥. 목록 길이가 가변이라 여기만 내용 높이 |

### 큰 타일과 작은 타일의 역할 분리 (이번 개편의 핵심)

hero에 있던 `시간 / 맨위크 / 건수` 숫자 줄(`.hero-metrics`)을 **작은 지표 타일로 내보냈다.** 큰 타일이 숫자를 붙들고 있으면 작은 타일이 "압축 요약"할 거리가 없어져 모자이크가 성립하지 않는다. 대신 hero의 넓어진 면적은 새 요소가 채운다:

- **요일별 기록 스트립** — 이 앱의 한 주(금~목) 7일을 미니 세로 막대로. 채워진 날 `--accent`, 빈 칸 `--surface-sunken`, 오늘만 `--accent` 테두리. 하루 8h를 100%로 잡는다.
- 왜 넣었나: 큰 타일이 제목+버튼만 담으면 **"큰데 텅 빈 카드"**가 되어 개편이 역효과가 난다. 이 스트립은 새 데이터가 필요 없다 — 이미 있는 일일 기록(DailyNote)의 날짜별 시간 합이다(**backend에 새 필드 요청 불필요**).

### 지표 4개를 고른 기준

"지금 손을 대야 하나"를 **한 숫자로** 답할 수 있는 것만 골랐다.

1. **이번 주 시간** (`32h` / sub: 보고 항목 N건)
2. **이번 주 맨위크** (`0.80` / 0.8 미만이면 `--danger-fg`)
3. **기한 지난 할 일** (`2건` / 0보다 크면 `--danger-fg`, sub: 오늘 마감 N건) ← TODO의 압축 요약
4. **진행중 프로젝트** (`3개` / sub: 평균 진행률 N%)

보고서가 없는 주(`status === "empty"`)면 1·2는 `—` + "아직 작성 전"으로 떨어진다.

## 4. TODO 리스트 (기능 스코프는 v6 그대로, 형태만 조정)

- **카드 제목을 "TODO 리스트"로 확정**(v6의 "앞으로 할 일"은 사용자 기각). "한 일 / 할 일" 한 글자 차이 문제도 영문 TODO가 자연히 해결한다.
- 필드(`id/dueDate/text/done/priority`), 기한 지남 그룹, 우선순위 3단계 pill, 완료 항목 접기, `.md` 미포함 문구 — **전부 v6 그대로**. 재논의하지 않았다.
- 벤토에 맞춰 바꾼 것 **둘뿐**:
  1. 목록 영역을 `.tile-body`(내부 스크롤)로 감싸고, 제목/추가 입력줄/안내 문구는 타일에 고정 — 스크롤해도 "추가하는 자리"가 사라지지 않는다.
  2. `TODO_VISIBLE` **6 → 8**. 타일이 746px로 길어져 6건만 그리면 아래가 200px 가까이 비어 "내용이 모자란 큰 카드"가 된다. 데모 데이터도 미완료 10건으로 늘려 `+2건 더 보기`가 여전히 보이게 했다.
- 카드 폭이 320 → **352px**(내부 264 → 296px)로 넓어져 할 일 문장이 덜 접힌다.

## 5. 고정 높이 타일의 넘침 처리

`.tile-body{flex:1; min-height:0; overflow:auto}` — 머리(제목·입력줄)와 발(요약·안내)은 늘 보이고 **가운데 목록만 안에서 스크롤**한다. 적용 대상: 오늘 한 일 / TODO / 맨위크 주별 바 / 진행중 프로젝트.

- 근거: 기록을 적는 입력줄이 스크롤 밖으로 밀려나면 그 타일의 존재 이유가 사라진다.
- 좌우 여백은 `margin:0 -6px; padding:0 6px`로 되돌려 스크롤 영역이 포커스 링을 자르지 않게 했다.

## 6. 반응형

| 폭 | 동작 |
|---|---|
| **> 1180px** | 위 12컬럼 모자이크 그대로. `main`이 1140px에서 캡되므로 이 구간에서는 실치수가 항상 동일하다(1920/125% = 1536px 노트북도 여기 해당). |
| **≤ 1180px** | 6컬럼으로 접는다. **행 스팬을 전부 해제**(`grid-row:auto`)해 타일이 제 내용 높이를 갖고, 고정 높이가 사라지므로 **내부 스크롤도 끈다**(스크롤 안의 스크롤 방지). hero/오늘 한 일/TODO는 전폭, **지표 4개만 3칸씩 남겨 2×2 블록 유지** — 이게 남아야 벤토의 흔적이 유지된다. 맨위크/진행중도 2열. |
| **≤ 700px** | 2컬럼. 지표만 2개씩, 나머지 전폭 세로 스택. |

## 7. QA가 검증 가능한 기준

1. 대시보드 첫 화면에 **크기가 서로 다른 타일**이 있다: 이번 주(가장 큼) / 지표 4개(가장 작음) / 오늘 한 일·TODO(가장 김).
2. hero 타일에 숫자 지표 줄(`시간·맨위크·건수`)이 **없다** — 그 숫자는 옆 작은 타일 4개가 받는다(중복 노출 금지).
3. hero 타일 하단에 **7칸** 요일 스트립이 있다(금~목). 기록이 있는 날만 `--accent` 막대가 차고, 오늘 칸만 `--accent` 테두리다.
4. 지표 타일 숫자는 **40px**, 라벨은 `.kicker`(대문자 자간), 보조 문구는 11.5px.
5. `이번 주 맨위크` 타일은 0.8 미만일 때만 숫자가 `--danger-fg`. `기한 지난 할 일` 타일은 값이 1 이상일 때만 `--danger-fg`.
6. TODO 카드 제목은 **"TODO 리스트"**다("앞으로 할 일" 아님).
7. 완료 배지 초록(`--good`), 이월 배지 주황(`--warn`), 위험 강조 빨강(`--danger`) — **v6과 동일**. 새 색이 추가되지 않았다(`oklch(` 정의는 `:root` 두 블록에만 존재).
8. `prefers-color-scheme` / 다크 팔레트 코드가 **한 줄도 없다**.
9. 과거 보고서 행은 타일 안에서 **테두리 없는 행 + 얇은 구분선**으로 나온다. 히스토리 탭의 같은 컴포넌트(`.hist-card`)는 **여전히 카드 형태**다(`.dash-list.flush` 스코프 안에서만 다르다).
10. 1180px 이하로 줄이면 타일 안 스크롤이 사라지고 타일이 내용 높이로 늘어난다.

## 8. frontend에게 넘길 때의 경계 (승인 후)

- 시각 스타일·타일 크기 배정·문구는 목업 그대로. **`<script>`의 상태 배열/이벤트 위임/`renderDashboard()` 재렌더 로직은 이식하지 않는다** — 서버 렌더링 + htmx로 대체한다.
- 벤토는 **순수 CSS Grid**다. Thymeleaf로 옮길 때 중요한 것은 **타일을 이 순서대로 출력하는 것**뿐이다(`hero → 지표4 → 오늘 한 일 → TODO → 맨위크 → 진행중 → 과거 보고서`). JS 배치 계산 없음.
- htmx로 부분 갱신할 때 **타일 하나를 통째로 `outerHTML` 교체**하면 그리드 배치가 유지된다(타일이 그리드 아이템 그 자체이므로). 타일 내부만 갈아끼우면 `.tile-body` 스크롤 위치만 초기화되고 배치는 영향 없다.
- 지표 타일 4개는 값이 바뀔 일이 많으므로(할 일 체크 등) **한 덩어리로 묶어 갱신**하는 편이 낫다 — 다만 그 경우에도 `.t-metric` 4개가 형제로 남아야 2×2가 유지된다(래퍼 div로 감싸면 그리드가 깨진다).
- 요일 스트립은 새 데이터가 필요 없다 — 기존 일일 기록의 `date`별 `hours` 합이다.

## 9. 사용자 확인이 필요한 지점

1. 타일 크기 배정이 실제 사용 빈도와 맞는지 — 특히 **오늘 한 일(8×6)이 TODO(4×10)보다 넓은** 배분.
2. hero의 **요일별 기록 스트립** 도입(큰 타일을 채우기 위한 신규 요소).
3. hero에서 숫자 지표를 빼 작은 타일로 분리한 것.
4. 지표 4종 선정(시간 / 맨위크 / 기한 지난 할 일 / 진행중 프로젝트).
5. `TODO_VISIBLE` 6 → 8.
6. 밀도 상향(간격 22→14, 패딩 26/28→20/22)이 답답하지 않은지.

## 10. 알려진 제약 (이번 변경과 무관)

목업의 "md로 내보내기"는 blob 다운로드라 **Artifact 뷰어에서는 파일이 저장되지 않는다**(뷰어가 페이지발 다운로드를 차단). 목업 v6부터 있던 제약이고 실제 앱(서버 첨부파일 응답)에는 해당되지 않는다.
