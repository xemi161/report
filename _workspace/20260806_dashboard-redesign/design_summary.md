## 1. IA: 3탭(대시보드 / 작성 / 히스토리), 기본 진입 = 대시보드

**결정**: 기존 2탭을 없애지 않고 앞에 대시보드를 추가한다. `.seg` 탭 순서는 `대시보드 · 작성 · 히스토리 · N`.

**근거**:
- 대시보드의 "과거 보고서 최근 5개"와 히스토리 탭은 역할이 다르다 — 전자는 *바로가기*(최근 것만), 후자는 *전체 아카이브*.
  대시보드에 5개만 두고 히스토리를 없애면 6번째 이전 보고서에 접근할 방법이 사라진다.
- 반대로 히스토리를 대시보드 안에 통째로 접어 넣는 안(2탭 유지)도 검토했으나, 대시보드가 스크롤 긴 목록 화면이 되어
  "한눈에 보는 요약"이라는 랜딩 목적이 훼손된다.
- 대신 중복을 의미 있게 만든다: 대시보드 목록 헤더 우측에 `전체 N개 보기 →`(`.link-more`) 버튼을 두어
  둘의 관계를 명시한다. 5개 이하일 땐 이 버튼을 렌더하지 않는다.

**주차 페이저는 "작성" 탭에서만 노출**한다. 대시보드/히스토리에서는 `visibility:hidden`으로 숨긴다
(`display:none`이면 헤더 폭이 튀어 탭 전환 때 레이아웃이 흔들린다). 라우팅상 페이저는 `week` 파라미터를 가진
작성 화면에만 의미가 있다.

**라우팅 제안** (backend/frontend 확정 필요):

| 화면 | 경로 |
|------|------|
| 대시보드(랜딩) | `/` |
| 작성 | `/entry?week=yyyy-MM-dd` |
| 히스토리 | `/history` |

`/`가 현재 `/entry`로 가는(또는 같은 화면을 렌더하는) 동작을 대시보드로 바꾸는 것이 이번 변경의 핵심이다.
`/history/{id}` → 해당 주 작성 화면 리다이렉트 관례는 그대로 둔다.

## 2. 이번 주 카드 (hero) — 신규작성 버튼의 자리

사용자 요청엔 "신규작성 버튼 존재"만 있었지만, 버튼만 떠 있으면 **어느 주를 쓰는 건지**가 화면에 없다.
그래서 대시보드 최상단에 "이번 주" 카드를 두고 그 안에 CTA를 넣었다.

**상태별 표시 (검증 가능한 기준)**:

| 이번 주 상태 | 배지 | 버튼 라벨 | 버튼 스타일 | 클릭 동작 |
|---|---|---|---|---|
| 보고서 없음 | `미작성` (`.badge.idle`, 회색) | **신규 작성** | `.btn` (accent 채움) | 이월 포함 초안 생성 → 작성 화면 |
| 작성중(draft) | `작성중` (`.badge.draft`, accent-soft) | **이어서 작성** | `.btn` (accent 채움) | 작성 화면으로 이동 |
| 제출됨(submitted) | `제출됨` (`.badge.done`, 초록) | **수정하기** | `.btn.outline` | 작성 화면으로 이동 |

- 보고서가 있으면 배지 아래에 `총 시간 / 맨위크 / 항목 수`를 인라인으로 보여준다(맨위크 < 0.8이면 `--danger-fg`).
- 보고서가 없으면 대신 안내 문구: "아직 작성을 시작하지 않았습니다. 지난주 미완료 항목은 자동으로 이월되어 채워집니다."
- **"신규 작성"은 빈 화면을 거치지 않는다** — 누르는 즉시 이월 초안을 만들고 작성 화면으로 간다.
  (기존 작성 탭의 "작성 시작" 빈 상태 화면은 *미래 주*로 페이저를 넘겼을 때를 위해 그대로 남겨둔다.)
- **대시보드에서 accent `.btn`은 이 버튼 하나뿐**이다. 나머지 액션(전체 보기)은 `.link-more` 고스트.
  진한 버튼이 여러 개면 이 디자인 시스템의 위계가 깨진다.

**확정**: 상태별 라벨 방식으로 간다(한 문구 고정 안은 반려).

## 3. 최근 2주 평균 맨위크 카드

**4주가 아니라 2주다.** 기존 `EntryService.recentAverageManWeek()`는 최근 **4주** 평균이므로 그대로 쓸 수 없다.
→ backend 작업: 기간을 파라미터로 받게 하거나(`recentAverageManWeek(int weeks)`) 2주용 계산을 신설해야 한다.
목업의 `RECENT_WEEKS_FOR_AVG = 2` 상수가 이 값에 대응한다.

**모집단 정의**: 이번 주를 제외한, **제출된** 최근 2개 보고서. 즉 "직전 2주"가 아니라
"제출본이 존재하는 최근 2건"이다(보고서가 없거나 초안 상태인 주는 건너뛴다 — §5의 draft 제외 결정과 같은 기준).
평균 낼 보고서가 없으면 빈 상태 문구.

**카드 구성**:
- 큰 숫자(34px, `.mw-big`) — 0.8 미만이면 `--danger-fg`
- 부제: "기준 1.00 · 0.8 미만이면 낮음으로 표시"
- 하단에 구성 주차를 하나씩 나열(주차 라벨 / 맨위크 / 얇은 5px 진행바). **"최근 2주"가 어느 주인지 화면에서
  검증 가능해야** 숫자를 신뢰할 수 있어서 넣었다. 바 폭은 맨위크 × 100%, 100% 초과 시 클램프.

## 4. 진행중인 프로젝트 카드

**"2건" 같은 숫자만 보여주는 건 정보가 없다**고 판단해 목록형으로 설계했다. 행마다:
프로젝트명 + 일감번호 pill + 진행률(%) + 진행바 + `최근 보고 · {주차 라벨}`.

**"진행중" 판정 기준 (구현 시 확정 필요)**:
- 실제 앱에서는 **`Project.active == true`가 1차 필터**가 된다. 이 카드가 `Project.active`를 집계/표시에
  실제로 쓰는 **첫 사례**다 — 지금까지는 카드 삭제 시 비활성 처리에만 쓰였고,
  CLAUDE.md "다음에 할 일"의 미결 항목("`Project.active` 집계/표시 방식 미정")이 이 화면으로 해소된다.
- 목업은 전역 프로젝트 목록이 없어서 근사치로 구현했다: 최근 보고서 4건(`PROJECT_LOOKBACK`)을 최신순으로 훑어
  일감번호 기준 중복 제거 후, **가장 최근 진행률이 100% 미만**인 것만 남긴다.
- **진행률 = 그 프로젝트 세부 항목 완료율의 평균(반올림)**. `projectProgress()` 참고.
  (최댓값이 아니라 평균인 이유: 분석/설계 100% + 개발 20%인 프로젝트를 100%로 보이게 하면 안 됨.)

→ backend 확인 필요: `Project.active`만으로 거를지, 아니면 "active AND 최신 보고 진행률 < 100"으로 거를지.
후자면 프로젝트별 최신 `ReportItem` 조회가 필요하다.

## 5. 과거 보고서 최근 5개 리스트

- 히스토리 탭의 `.hist-card`를 **그대로 재사용**한다(새 컴포넌트 없음 → frontend는 기존 프래그먼트를 재사용 가능).
- 대시보드는 `RECENT_REPORTS_ON_DASH = 5`로 자르고, 히스토리 탭은 전체를 보여준다.
- **카드 클릭 → 해당 주 작성(수정) 화면**. 이 앱엔 읽기전용 상세 화면이 없다(제출=비잠금 정책).
  기존 `/history/{id}` → 작성 화면 리다이렉트와 같은 패턴.

**모집단 = 제출된(submitted) 보고서만 (사용자 확정)**. 초안(draft)까지 포함해 상태 배지로 구분하는 안을
시안에 넣었다가 **반려됐다**. 대시보드 최근 5개 목록과 히스토리 탭 둘 다 **기존 규칙(submitted 전용)을 유지**하고,
탭 라벨의 건수도 제출본 기준이다. 작성 중인 초안은 대시보드 "이번 주" 카드나 작성 탭의 주차 페이저로 접근한다.

이 결정에 따라 목록 카드에는 **상태 배지를 달지 않는다** — 전부 제출본이라 "제출됨" 배지가 정보를 주지 못한다.
카드에 남는 배지는 맨위크가 낮을 때의 경고뿐이다.

**배지 색 규약 (QA 검증 기준)**:

| 배지 | 쓰이는 곳 | 클래스 | 색 토큰 |
|---|---|---|---|
| 제출됨 | 이번 주 카드만 | `.badge.done` | `--good-bg` / `--good-fg` (초록) |
| 작성중 | 이번 주 카드만 | `.badge.draft` | `--accent-soft` / `--accent-soft-fg` (블루) |
| 미작성 | 이번 주 카드만 | `.badge.idle` | `--surface-sunken` / `--text-muted` (회색) |
| 이월 | 작성 화면 항목 행 | `.badge.carry` | `--warn-bg` / `--warn-fg` (주황) |
| 맨위크 낮음 | 과거 보고서 카드 | `.badge.carry` + `.low-stripe` | 주황 배지 + `--danger-border` 좌측 스트라이프 |

## 6. "작성" 탭 상단 통계 카드 변경 (부수 변경)

기존 작성 탭은 `최근 4주 평균 맨위크` / `진행중 프로젝트 수`를 보여줬다. 이 두 지표는 이제 대시보드가 소유한다.
같은 카드가 두 화면에서 서로 다른 기간(4주 vs 2주)을 뜻하면 혼란이므로, **작성 탭 통계는 "지금 보고 있는 주"의
값으로 바꿨다**: `총 투입시간 / 맨위크 / 항목 수`. 제출 전에 맨위크가 0.8 미만인지 확인하는 게 이 자리의 실제 용도다.
제출된 주에는 통계 행 아래에 기존 `.locked-banner`가 그대로 붙는다(문구에서 중복되던 시간·맨위크는 뺐다).

⚠️ **frontend 구현 주의**: 이 통계는 항목을 인라인 편집할 때마다 값이 달라져야 하는데,
인라인 필드는 `hx-swap="none"`이라 서버 재렌더가 없어 **그대로 두면 값이 낡는다**.
완료율 100% "완료" 배지와 **같은 패턴으로 `static/js/app.js`에서 클라이언트 계산으로 갱신**해야 한다.
(구조 변경 동작은 `#writeView` 전체를 outerHTML로 갈아끼우므로 그때는 자동으로 맞는다.)

## 7. 새로 추가한 CSS (기존 토큰만 사용, 새 오클치 값 없음)

`.dash-grid`(330px + 1fr, 860px 이하 스택), `.section-head`, `.link-more`, `.hero` 계열, `.kicker`,
`.badge.draft` / `.badge.idle`, `.bar` / `.bar > i`(5px 진행바), `.mw-*`(맨위크 카드), `.proj-row`(프로젝트 행),
`.dash-list`.

- 진행바는 이 시스템에 없던 유일한 새 형태다. 트랙 `--surface-sunken`, 채움 `--accent`,
  낮은 맨위크일 때만 `--danger-border`. 높이 5px, `border-radius:999px`로 기존 pill 스케일을 따른다.
- 카드 라운드 18px, 배지 999px, 얇은 보더 위주, 그림자는 hover 시 `--shadow-sm`만 — 기존 규칙 그대로.
- 다크모드 관련 코드는 추가하지 않았다(단일 라이트 톤 고정 유지).

## 8. frontend 경계 (구현 착수 시 상기할 것)

목업의 시각/구조/문구/상태 규칙은 기준이지만, `<script>`의 상태 배열·이벤트 위임 로직은 **이식하지 않는다**.
대시보드는 서버가 계산해 렌더하는 정적 화면에 가깝다(htmx 배선이 거의 필요 없음 — 링크 이동과
"신규 작성" 폼 전송 정도). 목업의 `WEEKS` 배열/`computeTotals`/`activeProjects`는 어디까지나
"이 숫자가 이렇게 나와야 한다"는 명세를 눈으로 보여주는 장치다.

## 9. 목업 데모 데이터 변경

주차를 7건으로 늘렸다(7월 1주 ~ 8월 2주). 8월 2주 = 이번 주(미작성), 8월 1주 = 제출됨.
과거 보고서가 6건이라 대시보드는 5개 + `전체 6개 보기`가 자연스럽게 나온다.
7월 2주만 맨위크 0.72로 낮게 잡아 붉은 스트라이프 + "맨위크 낮음" 배지를 볼 수 있게 했다.
현재 렌더 값: 최근 2주 평균 **0.99**, 진행중 프로젝트 **2건**(GTPP 60%, 2차인증 리뉴얼 20%).

| 3 | 과거 보고서 목록에 draft 포함 | **반려 — 제출된(submitted) 보고서만** (§5 참고) |
| 4 | 진행중인 프로젝트 카드 | **목록형 유지** — 시안 그대로. 숫자 한 개짜리 통계 카드 안은 반려 |

### 3번 결정에 따른 목업 변경 (승인 후 반영 완료)

시안에는 "쓰다 만 초안이 목록에서 사라지면 되찾을 길이 없다"는 이유로 draft를 포함시켰으나 반려됐다.
과거 보고서 목록은 **제출본 아카이브**라는 것이 확정된 성격이다. 되돌린 내용:

- `pastReports()` 필터를 `status !== "empty"` → **`status === "submitted"`** 로 변경.
  이 함수는 대시보드 최근 5개 목록·히스토리 탭 목록·탭 라벨 건수·최근 2주 평균 맨위크 모집단·
  진행중 프로젝트 탐색 범위가 **모두 공유**하므로, 한 곳만 고치면 전부 일관되게 제출본 기준이 된다.
- 과거 보고서 카드(`histCardHtml()`)에서 **상태 배지 호출을 제거**했다 — 전부 제출본이라 무의미하다.
  카드에 남는 배지는 "맨위크 낮음"뿐이다.
- `statusBadge()`는 **이번 주 카드(hero) 전용**으로 역할이 좁아졌다(미작성/작성중/제출됨 3상태).
  `.badge.draft` / `.badge.idle` CSS는 hero가 계속 쓰므로 유지한다.
- 빈 상태 문구를 "아직 작성한 보고서가 없습니다" → **"아직 제출된 보고서가 없습니다"** 로 되돌렸다
  (기존 히스토리 화면 문구와 동일).

### frontend 구현 시 주의 (재확인)

- 목록 쿼리는 `status = submitted` 조건을 유지한다. 기존 히스토리 조회 로직을 그대로 쓰고,
  대시보드에서는 **최근 5건으로 limit만 걸면 된다**(새 필터 조건 없음).
- §6의 작성 탭 통계 갱신 문제(인라인 편집 시 `hx-swap="none"`이라 값이 낡음 → `app.js` 클라이언트 계산)는 그대로 유효하다.
- §8의 경계도 그대로다 — 목업 `<script>`의 상태 배열/이벤트 위임 로직은 이식하지 않는다.
