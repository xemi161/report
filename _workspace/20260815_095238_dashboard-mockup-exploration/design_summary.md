## 3. 추천 우선순위

**보수적 순서(위험 낮음 → 높음)**: ① → ⑩ → ④ → ② → ⑥ → ⑦ → ⑤ → ⑨ → ③ → ⑧

**설계적으로 추천하는 순서**는 다르다:

1. **② 벤토(현재 후보)를 기본 후보로 유지**한다. 다만 **TODO 기능과 레이아웃 결정을 분리**할 것을 권한다 — 지금은 "벤토를 승인 = TODO 도입도 승인"이라 둘 중 하나에 대한 반대가 다른 하나를 막는다. TODO 자리에 `진행중 프로젝트`를 세로로 세워 넣으면 신규 기능 없이도 같은 모자이크가 성립한다.
2. **⑥ 캘린더 또는 ⑧ 타임라인을 진지한 대안으로 검토**한다. 이 둘만이 "주차 요약"이 아니라 **날짜**를 축으로 삼는데, 이 앱에서 실제로 매일 여러 번 손대는 데이터는 일일 기록이다(주간 지표는 주 1~2회만 본다). 즉 손대는 빈도로 보면 날짜 축이 정직하다.
3. **③ 서술형은 부분 채용**을 권한다. 전면 채용은 마찰이 크지만, **한 문장짜리 해석 줄**은 어느 시안에든 붙는다(예: hero 아래 "평균보다 0.12 낮습니다"). 지금 화면은 `0.80`만 보여주고 좋은지 나쁜지는 사람이 판단하게 두는데, 이게 이 대시보드의 가장 큰 빈틈이다.
4. **⑤·⑨는 "고르는 안"이 아니라 경계를 보여주는 안**이다. ⑤는 "대시보드를 어디까지 채워도 작성 탭을 안 잡아먹는가", ⑨는 "카드를 안 쓰면 얼마나 조용해지는가"의 양 끝이다.
5. **⑩은 반드시 ②와 나란히 보시길** 권한다. 두 안의 차이가 곧 "위계를 레이아웃으로 만들 것인가"에 대한 답이고, 그게 v7 피드백의 원래 질문이다.

## 4. 조합 제안 (하나를 고르지 않아도 되는 길)

- **A안 — ② + ③의 문장 한 줄**: 벤토 hero의 부제를 고정 문구에서 "평균보다 0.12 낮습니다" 같은 해석 문장으로. 레이아웃 리스크 없이 ③의 핵심 이득만 가져온다. **가장 싸고 가장 효과가 큰 조합.**
- **B안 — ② + ⑥의 캘린더**: 벤토 hero의 요일 스트립(막대 7개)을 ⑥의 7컬럼 미니 캘린더로 승격. 스트립은 "얼마나"만 보여주지만 캘린더는 "무엇을"까지 보여준다. hero가 6×4로 커진 만큼 들어갈 자리가 있다.
- **C안 — ④ + ⑦**: 좌측 레일에 주간 숫자를 고정하고, 우측 본문 최상단을 프로젝트 카드로. 주차와 프로젝트 두 축을 좌/우로 분업시킨다.
- **D안 — ⑧ + ①**: 대시보드는 ①처럼 두되, "오늘 한 일" 카드만 ⑧의 타임라인 형태로. 화면 전체를 피드로 만들지 않고 시간 감각만 빌려온다.

## 5. 사용자에게 물어볼 것

1. 대시보드의 축을 **주차**로 둘지 **날짜**로 둘지 — 이게 10개를 가르는 가장 큰 분기다(①②③④⑤⑨⑩ vs ⑥⑧, ⑦은 제3의 축).
2. 대시보드가 **이번 주 항목 실체(⑤)까지 보여줘도 되는지**, 아니면 요약에 머물러 작성 탭과 역할을 나눠야 하는지.
3. 숫자에 **해석 문장(③)**을 붙이는 게 도움이 되는지, 잔소리로 느껴지는지.
4. **위젯 재배치(⑩)**를 언젠가 하고 싶은지 — 그렇다면 균일 그리드를 미리 깔아두는 게 싸다(벤토는 순서가 곧 배치라 재배치가 어렵다).
5. ②를 계속 간다면 **TODO 기능과 레이아웃을 분리 승인**할지.

## 6. frontend에게 넘길 때의 경계 (승인 이후, 지금은 아님)

- 이 파일의 `<script>`(데모 데이터 배열, `render*()` 문자열 조립, 칩 전환)는 **전부 목업 전용이며 이식 대상이 아니다.** 실제 앱은 서버 렌더링 + htmx로 같은 책임을 진다.
- 이식할 것은 **CSS와 DOM 구조뿐**이다. 시안 선택기(`.picker`)와 가짜 앱 헤더(`.appbar`)는 이 탐색 파일에만 있는 크롬이라 이식 대상이 아니다.
- ②를 고를 경우 **타일을 DOM에 넣는 순서가 곧 배치**다(`grid-auto-flow`는 dense가 아니다). ⑩은 반대로 순서에 무관하다.
- ⑥만 `main`을 1240px로 넓히는데, 이건 작성 탭의 `body.wide`(1670px)와 **다른 값이고 다른 근거**다(캘린더 7컬럼 최소 폭). 두 값을 통일하지 말 것.

## 7. QA가 검증 가능한 기준 (이 탐색 파일 자체에 대해)

1. 상단 칩 10개, 클릭/←→ 키로 전환되고 URL 해시(`#c1`~`#c10`)가 따라 바뀐다.
2. 10개 시안 전부 헤더의 탭이 **대시보드/작성/히스토리 3개**이고 "대시보드"가 활성이다.
3. 어느 시안에서도 이번 주 총 시간은 **32h**, 맨위크 **0.80**, 항목 **7건**, 2주 평균 **0.92**, 진행중 프로젝트 **3개**로 동일하다.
4. 맨위크 0.8 미만은 전부 `--danger-fg`(빨강), 완료 배지는 `--good`(초록), 이월 배지는 `--warn`(주황). 새 색은 없다.
5. `oklch(` 정의는 `:root` 두 블록 안에만 존재한다(버튼 글자색 `oklch(100% 0 0)` 제외).

7. 강한 accent `.btn`은 각 시안에 **정확히 1개**(주 CTA "이어서 작성")다 — 실측 확인함. "md로 내보내기"는 `.btn.outline`, 나머지 액션은 전부 `.ghost` / `.link-more`다.

9. ②에만 TODO 리스트가 있다. 나머지 9개에는 "할 일"이라는 단어가 없다.
